# 施工 Wiki

把 QQ 群里的施工聊天整理成**可查、可交付**的资料：按天递进的聊天记录、施工日志、单价台账。

## 数据三层（每个项目自成一套）

```
<项目根>/
└── <项目名>/                       ← 群名 = 项目名
    ├── raw/                        原始归档（机器格式，只追加不改）
    │   ├── 消息/2026-11-08.jsonl
    │   └── 图片/2026-11-08/
    ├── 结构/                       结构层（人可读，按 年.月/日 递进）
    │   ├── index.md                项目索引 → 月份
    │   └── 2026.11月/
    │       ├── index.md            月索引 → 日期
    │       └── 08/
    │           ├── index.md        当日概览
    │           ├── 聊天记录.md      当天全部消息
    │           ├── 图片/            硬链接到 raw，不占额外空间
    │           └── events.jsonl     结构化事件（台账的数据源）
    └── 输出/
        └── 施工日志与单价台账.xlsx
```

**一个项目一个目录，raw / 结构 / 输出 都在里面，互不干扰。**

## 生成流程

一条命令完成「结构层 + Excel」（对所有项目）：

```
wiki_build            # 或者：wiki_build({ root: "/自定义路径" })
```

底层做两件事：

1. `build-structure.mjs` — 读 `~/.dsh-qq-access/data/messages/*.jsonl`，按项目/天拆分，生成结构层
2. `build-excel.py` — 从 `events.jsonl` 抽取字段，写 Excel

**两步都是纯规则，不调用模型，不消耗 token。**

## Excel 结构

### 施工日志

| 列 | 来源 |
| --- | --- |
| 项目名称 | 群名 |
| 日期 | 消息日期 |
| 拍摄时间 | 消息时间（有图片 EXIF 时可用图片时间） |
| 天气 | 从当天任意消息里匹配 晴/多云/阴/小雨… |
| 地点 | 匹配桩号 `K1+200`、`3号路`、`一标段` |
| 建设/施工/监理单位 | 匹配「XX单位：XXX」 |
| 分项工程 | 关键词归类到 路基/路面/挡土墙/桥涵/排渠 |
| 部位 | 留空（需模型抽取） |
| 事项 | 消息原文（截断 120 字） |
| 图片 | 留空（需关联图片路径） |

### 单价台账

| 列 | 规则 |
| --- | --- |
| 单位 / 数量 | 匹配 `N方`、`N吨`、`N个`、`Nm²` |
| 单价 | 匹配 `480元/方`、`单价 480`、`480元每方` |
| 金额 | 数量 × 单价，两者都有才算 |
| 依据原文 | 原消息全文 |
| 备注 | 只有数量没有单价时标「原文未提及单价」 |

**核心原则：抽不到就留空，绝不编造。**

## 分项体系（道路工程）

```
路基   ← 清表、土方、填筑、压实、路床、边坡、换填、软基
路面   ← 底基层、基层、面层、沥青、水稳、碎石垫层
挡土墙 ← 挡墙、墙身、泄水孔、墙背回填
桥涵   ← 桩基、承台、台身、梁板、盖梁、桥面、涵洞、墩柱
排渠   ← 沟槽、管道、检查井、雨水管、污水管、箱涵、盖板
```

## 技能更新

插件仓库：`dawalixi1980/nas-dajun`

```
wiki_check_update     # 检查 GitHub 是否有新提交
wiki_status           # 看当前版本、项目列表、更新状态
```

**当仓库更新时**：
1. 插件会记录本地对应的 commit
2. 面板提示「有新版本」
3. 确认后同步技能定义与工具脚本
4. **同步会重建结构层**（因为工具规则可能变了），此时会明确提示

## 使用建议

- 每天定时跑一次 `wiki_build`，或在群里说「生成今天的施工日志」
- 图片分析（识别天气、地点、单位、部位）需要多模态模型，属后续版本
- 台账的单价只认原文明确写法；模糊表述（如「大概五百一方」）不记录
