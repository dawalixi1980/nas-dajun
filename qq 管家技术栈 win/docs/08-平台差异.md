# 08 平台差异：macOS 与 Windows

当前实现完全在 **macOS** 上开发，部分能力依赖 macOS 特性。移植到 Windows 需要改以下几点。

## 必然要改

| 项目 | macOS | Windows |
| --- | --- | --- |
| 路径分隔符 | `/Users/dada/…` | `C:\Users\…`，代码里用 `path.join` 已兼容 |
| 默认目录 | `~/项目文件` | 需改为实际路径，配置里写死的地方要改 |
| Python 路径 | `~/.dsh/dsh-runtimes/…/python/bin/python3` | 改为 `python.exe` 或随 DSH 的运行时路径 |
| 定时任务 | `launchd`（`~/Library/LaunchAgents/com.qq.*.plist`） | 计划任务（`schtasks`）或 `Startup` 文件夹 |
| 防休眠 | `caffeinate` | `powercfg /change standby-timeout-ac 0` |
| 文件选择器 | 原生 `NSOpenPanel` | 原生对话框需重新实现 |
| 中文文件名 | NFD 规范化 | NFC，跨平台同步时要注意 |
| 文件权限 | `chmod 600` | ACL，通常可忽略 |

## 不受影响

- QQ 机器人协议（WebSocket + HTTP API）—— 平台无关
- 归档格式（JSONL）—— UTF-8，平台无关
- Excel 生成（openpyxl）—— 跨平台
- 桥接结构（目录 + Markdown）—— 只要路径用 `join` 就没事

## 迁移建议

1. 把 `~/.dsh-qqbot` 整个目录复制过去（保留 `archive/`、`state.json`）
2. 改 `config.json` 里的 `root`
3. 重新安装 `audio`/插件依赖（`pnpm install`）
4. 定时任务重写（见上表）
5. 跑一次面板「立即整理」验证路径

## 硬链接

原施工 Wiki 用硬链接省空间。硬链接在 Windows 上需要 NTFS 且同盘，
跨盘会失败 —— 现在的实现改成**复制**，跨平台更稳，代价是占空间。

## Windows 落地状态（2026-11 实测）

Windows 11 + DSH 桌面端已跑通，下列改动已合并进 `plugins/`：

| 问题 | 现象 | 修改 |
| --- | --- | --- |
| Python 路径写死 macOS | 归档时 `施工日志.xlsx` / `单价台账.xlsx` 不生成 | `archive2/wiki.js` 按 `process.platform` 拼路径，支持 `DSH_PYTHON_BIN` 覆盖 |
| 未配 AppID 时 QQ 管家面板全 404 | 新装或刚解绑时面板空白 | `lib/index.js` 把 `mountArchive2()` 提到凭据检查之前，面板接口与机器人凭据解耦 |
| 面板「选择目录…」报 `SyntaxError: Unexpected end of JSON input` | 点按钮必弹错误 | `lib/client.js` 改调 `/qqbot/bots/pick-dir` + `POST /qqbot/bots {action:"update"}`，不再请求不存在的 `/qq-archive/v18/*` |
| 机器人配置无法落盘 | 面板保存报「未找到机器人 default」，重启即丢、需重新扫码 | `lib/setup/persist.js`：条目存在但没有 `config` 映射时就地补一个并视为已挂载，避免追加同 id 重复条目导致读回校验失败回滚 |

工作目录优先级（Windows 同样适用）：

```
该机器人自己的 cwd  >  插件全局 cwd  >  ~/.dsh-qqbot/workspace
```

多机器人时每个 `bots[]` 项各自带 `cwd`，面板「机器人管理」里每个卡片独立设置，互不影响。

踩坑记录：

- `grep` 类工具不能直接搜 `resources/app.asar` 内部路径，需先解包。
- 读取插件源码时注意控制台编码，UTF-8 文件在 GBK 终端里会显示成乱码，但不影响磁盘内容。
