# 01 · 整体架构

## 数据流

```
┌─────────────────────────────────────────────────────────────┐
│  QQ 服务器                                                    │
└───────────────┬─────────────────────────────────────────────┘
                │ 协议通信（非官方，有被踢风险）
                ▼
┌─────────────────────────────────────────────────────────────┐
│  LLBot（协议端，常驻）                                         │
│  · 登录 QQ 个人号                                              │
│  · 暴露 OneBot 11 HTTP 接口 :3000                              │
│  · 事件 POST 到 :5702                                          │
└───────────────┬─────────────────────────────────────────────┘
                │ HTTP POST（无签名）
                ▼
┌─────────────────────────────────────────────────────────────┐
│  shim（签名转发器，常驻）                                       │
│  · 用 HMAC-SHA1 补 X-Signature                                │
│  · 转发 :5702 → :5701                                         │
└───────────────┬─────────────────────────────────────────────┘
                │ HTTP POST（带签名）
                ▼
┌─────────────────────────────────────────────────────────────┐
│  dsh-qq-access（DSH 插件，进程内）                              │
│  · 校验签名                                                    │
│  · 过滤 selfId（只收当前登录号的消息）                           │
│  · 写 data/messages/<日期>.jsonl                               │
│  · 图片到达即下载原图                                            │
└───────────────┬─────────────────────────────────────────────┘
                │ 读取 JSONL
                ▼
┌─────────────────────────────────────────────────────────────┐
│  organizer（整理器，定时 60s）                                  │
│  · 按「群名_首次日期」拆文件夹                                   │
│  · 生成 聊天记录.md                                             │
│  · 图片硬链接到 blob 库                                         │
└───────────────┬─────────────────────────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────────────────────────┐
│  construction-wiki（DSH 插件，按需）                            │
│  · 按 项目/年.月/日 重组结构层                                   │
│  · 规则抽取 → 施工日志 + 单价台账 Excel                          │
└─────────────────────────────────────────────────────────────┘
```

## 为什么需要 shim

`dsh-qq-access` 强制校验 `X-Signature`（HMAC-SHA1），而 LLBot 发事件时不带签名。
shim 就是补这一层，让二者能对接。

```
LLBot → shim(算签名) → qq-access(验签名)
```

## 为什么归档要跑在 DSH 里

`dsh-qq-access` 是 DSH 插件，好处是能直接调用宿主能力（工具、面板、会话）。
代价是**DSH 关掉就不归档**。

如果只需要归档不需要对话，可以把这一层换成独立进程（直连 LLBot 的 WS），
但会失去 `qq_*` 工具与面板。

## selfId 过滤（最容易踩的坑）

```
插件只接受 event.self_id === 配置的 selfId 的消息
```

换号后如果不改 selfId，**所有消息被静默丢弃**，表面看"在运行"，实际什么都没收到。

处理机制：
- 插件启动时读一次 `selfId`，运行中不改
- 换号后必须重启 DSH
- `llbot-align` 守护会在换号时自动改配置并提示

## 关键路径

| 内容 | 路径 |
| --- | --- |
| 插件配置 | `~/.dsh-qq-access/config.json` |
| 原始消息 | `~/.dsh-qq-access/data/messages/*.jsonl` |
| 图片 blob | `~/.dsh-qq-access/data/media/blobs/` |
| 图片索引 | `~/.dsh-qq-access/data/media/<日期>.jsonl` |
| LLBot 数据 | `~/llbot/bin/llbot/data/` |
| LLBot 会话 | `~/llbot/bin/llbot/data/qq-session-<uin>.json` |
| 归档根目录 | 可配置，默认 `~/项目文件/群聊归档` |
| 运维脚本 | `~/.qq-organizer/` |
