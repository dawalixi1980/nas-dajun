# 自动化任务

把用户口头的「每天几点往哪个群发什么」变成一个真正会跑的定时任务。

**执行入口**：`bash <技能目录>/run.sh <命令>` —— `run.sh` 会自动找到 node（机器人子进程里 `node` 通常不在 PATH），再转给 `automation.mjs`。下文简写为 `run.sh`。

**存储**：走插件官方接口 `/qqbot/automation`，由运行中的引擎热更新 `~/.dsh-qqbot/automations.json`。**永远不要手改这个 JSON**，否则内存与磁盘不一致，面板显示的数据会对不上。

## 触发

用户表达以下意图时进入本流程：

- 「要实现一个自动化任务」
- 「加个定时任务」「每天 X 点往 Y 群发 Z」
- 「查一下 / 删掉 / 暂停我的自动化任务」

## 第一步：给填空表（别先追问一堆细节）

直接输出这张表：

```
请填写下面三项（其余我来补）：

1. 群聊名称：
2. 执行时间：
3. 任务内容：
```

可选（用户不填就用默认）：

```
4. 机器人：（默认＝当前会话绑定的机器人）
5. 只在工作日执行 / 只发一次：（默认＝每天）
```

**动手前先确认身份**：`run.sh whoami`，并把结果顺带告诉用户，例如：
「当前会话绑定的是**小宝**，第 4 项不填就建在它名下。」

## 第二步：解析

| 字段 | 怎么处理 |
| --- | --- |
| 群聊名称 | `run.sh groups --bot <id>` 查已登记群；找不到见「群名怎么确定」 |
| 执行时间 | 转成 5 段 cron（见对照表） |
| 任务内容 | 作为 `--prompt`，但必须符合下方「执行约束」 |
| 机器人 | `whoami` 的结果；或用户明确指定的 `--bot <id>` |

### 时间 → cron 对照表

5 段：`分 时 日 月 周`，本地时间，周字段 `0` 或 `7` 都是周日。

| 用户说法 | cron |
| --- | --- |
| 每天早 9 点 | `0 9 * * *` |
| 每天 18:30 | `30 18 * * *` |
| 工作日早 8 点 | `0 8 * * 1-5` |
| 每周一早 9 点 | `0 9 * * 1` |
| 每周一、三、五 20:00 | `0 20 * * 1,3,5` |
| 每月 1 号 10:00 | `0 10 1 * *` |
| 每 30 分钟 | `*/30 * * * *` |

⚠️ 只支持 5 段 cron，**没有秒字段，最小粒度是 1 分钟**。
「每 5 秒」「每 30 秒」这类需求**直接做不到**，不要勉强答应：
说明最小 1 分钟，并给出「每分钟一次」的替代方案让用户决定。

## 第三步：确认块（写入前必须给用户看）

```
机器人：小宝（1905830497）
目标群：新施工测试1群（54C0B985...）
执行时间：每天 09:00（cron 0 9 * * *）
任务内容：……
```

用户回答"好 / 可以 / 行"即视为确认。

## 第四步：写入

```bash
bash <技能目录>/run.sh add \
  --name "每日早报" \
  --cron "0 9 * * *" \
  --group "新施工测试1群" \
  --prompt "用三句话播报今天日期并提醒施工安全"
```

- 机器人默认取当前会话绑定；要指定加 `--bot <id>`
- 群可以传：群名、openid，或 `本群`（当前会话就在群里时）
- 私聊目标用 `--private <openid>`
- 任务名会自动加 `【机器人名】` 前缀，方便面板区分；不要就加 `--no-prefix`
- **拿不准先干跑**：加 `--dry-run` 只打印任务 JSON，不写盘

成功后打印任务 id、机器人、目标、时间。**把任务 id 告诉用户**，方便以后删除。

## 第五步：回执

```
✓ 已创建「【小宝】每日早报」
  任务 id：task-a1b2c3d4
  执行：每天 09:00
  目标：新施工测试1群
  查看全部：bash run.sh list
  删除：bash run.sh remove --id task-a1b2c3d4
```

## 多机器人隔离（铁律）

1. **机器人 id 只来自两处**：`whoami` 的结果，或用户明确指定的 `--bot`。**任何情况下都不要猜，也不要默认取第一个机器人。**
2. 群名 → openid 的解析**必须限定在该机器人名下**（`groups.json` 按 botId 分桶，脚本已强制）。
3. 每个任务都带 `action.botId`，引擎只会用这个机器人的模型与通道执行，不会串到别的机器人。
4. 帮 A 机器人建的任务，绝不能拿去给 B 用；**同名群在不同机器人下是不同的 openid**。
5. 用户说"另一个机器人也要"时，**单独再建一条**，不要复制同一个任务改字段。

## 执行约束（写任务内容时必须遵守）

定时任务触发时，引擎会：

- **新开一个会话**，没有对话历史
- **禁用所有工具**（不能读文件、不能联网、不能查库）
- 只把 prompt 发给模型，取最后一段文本**直接发到群里**
- **180 秒超时**

所以 `任务内容` 必须写成「让模型直接生成一段可发送文本」的指令：

| ❌ 不行 | ✅ 可以 |
| --- | --- |
| 读取昨天的日志汇总一下 | 用三句话总结今天该注意的施工安全事项 |
| 查一下天气再发 | 说明今天日期，并提醒大家注意降温保暖 |
| 把 Excel 里的进度发出来 | 生成一段 100 字左右的施工进度提醒 |

用户坚持要"查数据再发"时，说明这是引擎限制，需要换方式（人工触发或别的插件），不要硬写一个跑不出东西的任务。

**另外两条同样致命的限制：**

| ❌ 做不到 | 原因 |
| --- | --- |
| 发文件、发图片、发表格 | 只有文本通道，且无工具可生成文件 |
| 接龙、连续剧、累加统计等跨次依赖 | 每次都是新会话，**没有上一次的记忆** |

遇到这类需求，先说明限制，再给可行的降级方案（比如"每分钟一条成语"可以，"成语接龙"不行），**不要假装能做到**。

**还有一个平台级限制：**

- 定时任务往**群**里推送属于「主动消息」，QQ 开放平台默认不给权限，
  报错 `主动消息失败, 无权限`。建群任务前先说明这个风险，别承诺一定能发。
- **私聊**的主动消息通常放行，私聊任务可以正常用。
- 要往群里发，只能用**事件触发**（有人发消息后被动回复，会带 msg_id 通过权限校验），
  或者让用户去开放平台申请主动消息能力。

## 群名怎么确定

`groups` 里显示 `(未命名)` 的群，需要它的 openid 才能精确发送。

> ⚠️ **QQ 群号（如 768840065）不是 openid，不能用来发送。**
> 用户给群号时不要直接塞进 `--group`，必须换成群名或 openid。
> 另外：群号只说明"这个群存在"，不代表**当前机器人**在群里。不在群里的目标发不出去，先确认 `groups` 里有没有对应记录。

1. 先看 `groups` 输出里有没有 **openid 和群名都能对上**的记录；
2. 对不上就问用户：让他在那个群里 @机器人 发 `/id`，机器人会回复该群 openid；
3. 拿到 openid 后登记一次：

```bash
bash <技能目录>/run.sh learn --openid 54C0B9... --name 新施工测试1群
```

⚠️ **登记要写 `~/.dsh-qqbot/groups.json`，可能被文件沙箱拒绝（EPERM）。** 这不是 bug。届时按脚本提示处理：直接用 openid 建任务、或在桌面端会话执行、或手动补一行。**不要反复重试同一命令。**

## 常用命令

```bash
bash run.sh whoami             # 我是哪个机器人、在哪个群
bash run.sh bots               # 所有机器人及 id
bash run.sh groups --bot X     # 该机器人名下已知的群
bash run.sh list               # 全部任务（含启用状态、上次结果）
bash run.sh remove --id X      # 删除
bash run.sh toggle --id X --off    # 暂停
bash run.sh toggle --id X          # 恢复
bash run.sh run --id X         # 立即执行一次（测试用）
```

## 排错

| 现象 | 处理 |
| --- | --- |
| 连不上接口 | DSH 桌面端没运行；确认 `DSH_WEB_URL` 指向的端口在听 |
| 机器人 id 不存在 | 跑 `bots` 看真实 id，别拿名字当 id |
| 群找不到 | 用 `groups` 看已知列表，或按「群名怎么确定」走 |
| 任务建了不执行 | 检查 `enabled`、cron 是否匹配本地时间、机器人是否 `ready` |
| 上次结果是「模型没有返回文本」 | 任务内容太抽象，改成明确的产出指令 |
| `learn` 报 EPERM | 沙箱不允许写工作区外文件，见上文，别重试 |
| `主动消息失败, 无权限` | 平台未授予群主动推送权限；**群定时推送发不出去**，改用事件触发或私聊 |
