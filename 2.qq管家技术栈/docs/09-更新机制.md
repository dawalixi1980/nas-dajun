# 09 更新机制

仓库里的 `2.qq管家技术栈/plugins/` 是插件的**唯一源码来源**。
本机的插件目录通过更新器从仓库拉取。

## manifest.json

```json
{
  "name": "qq-butler-stack",
  "version": "1.0.0",
  "repo": {
    "url": "git@github-nas-dajun:dawalixi1980/nas-dajun.git",
    "branch": "main",
    "basePath": "2.qq管家技术栈"
  },
  "targets": [
    {
      "id": "dsh-qqbot-multi",
      "source": "plugins/dsh-qqbot-multi",
      "dest": "~/.dsh/profiles/desktop/node_modules/dsh-qqbot-multi",
      "include": ["lib", "package.json", "cordis.patch.yml", "cordis.yml"],
      "restart": true
    },
    {
      "id": "dsh-qq-butler",
      "source": "plugins/dsh-qq-butler",
      "dest": "~/项目文件/qq-butler",
      "include": ["index.js", "client.js", "cordis.patch.yml", "package.json", "icon.svg", "locale"],
      "restart": false
    }
  ]
}
```

- `source` 相对 `basePath`
- `dest` 支持 `~`
- `restart: true` 表示更新后需要重启 DSH 桌面端才生效
- 只覆盖 `include` 列出的内容，不动 `node_modules` 与本地数据

## 更新流程

```
1. 拉取：git -C ~/.dsh-qqbot/update-cache/nas-dajun pull
   （首次自动 clone）
2. 读 manifest.json，取 version
3. 与本机 ~/.dsh-qqbot/update-cache/applied.json 比对
4. 版本不同 → 按 targets 复制文件
5. 记录已应用的版本
6. 回复：更新了什么 / 是否需要重启
```

## 触发方式

| 入口 | 说明 |
| --- | --- |
| 群里或私聊发 `/update` | 命令直接执行，不经过模型 |
| 面板「检查更新」按钮 | 调用 `POST /archive2 {action:"update"}` |

两者走同一段代码。

## 安全约束

- 只复制 `include` 白名单内的路径
- 不删除目标目录里已有的文件（只覆盖同名）
- 拉取失败（网络/凭证问题）时原样报错，不动本地文件
- 更新前把被覆盖的插件目录备份到 `~/.dsh-qqbot/update-cache/backup-<时间戳>/`

## 更新后生效

- `dsh-qq-butler`：刷新页面即可（纯前端）
- `dsh-qqbot-multi`：需要重启桌面端，或在插件管理里禁用再启用
