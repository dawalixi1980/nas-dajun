# 01 架构总览

## 分层

```
QQ 开放平台
   │  实时事件（GROUP_MESSAGE_CREATE / GROUP_AT_MESSAGE_CREATE / C2C_MESSAGE_CREATE）
   ▼
dsh-qqbot-multi（宿主插件）
   ├─ QQBot SDK 连接层（每个 appId 一条 WebSocket）
   ├─ 中间件链（见下）
   ├─ Agent 会话（每个群 / 每个私聊一个 session）
   ├─ 归档模块 archive2（写入 ~/.dsh-qqbot/archive）
   ├─ 桥接模块 wiki.js（生成结构化工程信息）
   └─ 自动化引擎（cron 定时任务）
   │
   ▼
dsh-qq-butler（纯前端面板）
   └─ 读取 /archive2 接口，展示与操作
```

## 中间件链顺序（关键）

| 顺序 | 中间件 | 作用 |
| --- | --- | --- |
| 1 | errorHandler | 兜底 |
| 2 | messageFilter | 去重、跳过自身回声 |
| 3 | accessPolicy | 私聊/群白名单 |
| 4 | historyBuffer | 缓存最近 N 条（本实现 N=3） |
| 5 | mentionGate | 计算 `ctx.state.mention`，本实现一律放行 |
| 5.5 | **groupArchive** | 归档 + 按策略决定是否继续 |
| 6 | contentSanitizer | 去 @ 标记、表情标签 |
| 7 | rateLimiter | 限流 |
| 8 | slashCommand | 斜杠命令（群聊默认要求被 @，由 5.5 补标记绕过） |
| 9 | concurrencyGuard | 同会话串行 |
| 11.5 | attachmentProcessor | 附件下载 |
| 12 | envelopeFormatter | 组装上下文 |

**5.5 是最关键的一层**：它必须排在 mentionGate **之后**（才能读到 `wasMentioned`），又必须在 agent 之前（才能拦住消息）。这是踩过的坑。

## 数据流

```
入站消息
  → 中间件 5.5：下载媒体 → 写 archive/<日期>.jsonl
  → 策略裁决：silent(仅@) / off(不收集) / active(每条)
  → Agent 生成回复
  → 出站 send()：发送成功后同样写 archive（direction=out）
  → 每 5 分钟：整理到 QQ归档2 → 桥接生成工程信息 → 生成 Excel
```

## 设计原则

1. **先归档，再决策** —— 消息进来先落盘，策略只影响「回不回」，不影响「记不记」
2. **出站也归档** —— 机器人说的话同样是聊天记录的一部分
3. **规则优先，模型兜底** —— 工程要素用正则抽，抽不到就留空，不编造
4. **幂等重建** —— 桥接每次全量重建当天文件，改名后自动清理旧目录
